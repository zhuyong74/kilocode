# Code-Index 用户使用指南

## 1. 功能概述

### 1.1 什么是 Code-Index

Code-Index 是 Kilocode 项目中的智能代码索引和搜索功能，它通过先进的向量嵌入技术为您的代码库提供语义搜索能力。与传统的文本搜索不同，Code-Index 能够理解代码的语义含义，帮助您快速找到相关的代码片段、函数、类和文档。

### 1.2 核心价值

- **智能语义搜索**：基于代码含义而非仅仅文本匹配进行搜索
- **多语言支持**：支持 40+ 种编程语言和文件格式
- **实时索引**：自动监控文件变化并更新索引
- **高效检索**：使用向量数据库实现毫秒级搜索响应
- **上下文理解**：理解代码结构和语义关系

### 1.3 支持的文件类型

Code-Index 支持以下编程语言和文件格式：

**主流编程语言**：

- JavaScript/TypeScript (.js, .jsx, .ts, .tsx)
- Python (.py)
- Java (.java)
- C/C++ (.c, .h, .cpp, .hpp)
- C# (.cs)
- Go (.go)
- Rust (.rs)
- PHP (.php)
- Ruby (.rb)
- Swift (.swift)
- Kotlin (.kt, .kts)

**Web 技术**：

- HTML (.html, .htm)
- CSS (.css)
- Vue (.vue)
- Markdown (.md, .markdown)
- JSON (.json)

**其他语言**：

- Scala (.scala)
- Lua (.lua)
- Elixir (.ex, .exs)
- OCaml (.ml, .mli)
- Zig (.zig)
- Elm (.elm)
- Solidity (.sol)
- TOML (.toml)
- Visual Basic .NET (.vb)

## 2. 快速开始

### 2.1 启用 Code-Index 功能

1. 打开 VSCode 设置（Ctrl+,）
2. 搜索 "Code Index"
3. 找到 "Kilocode › Code Index: Enable" 选项
4. 勾选启用该功能

### 2.2 基本配置流程

启用功能后，您需要配置嵌入提供商：

1. 在设置中找到 "Kilocode › Code Index: Embedder Provider"
2. 选择一个嵌入提供商（推荐 OpenAI 或 Ollama）
3. 配置相应的 API 密钥或连接信息
4. 点击 "开始索引" 按钮

### 2.3 首次索引设置

首次使用时，系统会：

1. 扫描您的工作区文件
2. 过滤支持的文件类型
3. 解析代码结构
4. 生成向量嵌入
5. 存储到向量数据库

**注意**：首次索引可能需要几分钟时间，具体取决于代码库大小。

## 3. 详细配置指南

### 3.1 嵌入提供商配置

#### 3.1.1 OpenAI 配置

**适用场景**：追求最佳搜索质量，有 OpenAI API 访问权限

**配置步骤**：

1. 选择 "openai" 作为嵌入提供商
2. 输入您的 OpenAI API 密钥
3. 选择模型（推荐 text-embedding-3-small 或 text-embedding-3-large）
4. 配置 API 选项（可选）

**配置示例**：

```
嵌入提供商: openai
API 密钥: sk-your-api-key-here
模型 ID: text-embedding-3-small
模型维度: 1536
```

#### 3.1.2 Ollama 配置

**适用场景**：本地部署，注重数据隐私，无需外部 API

**配置步骤**：

1. 确保本地已安装并运行 Ollama
2. 选择 "ollama" 作为嵌入提供商
3. 配置 Ollama 服务地址（默认：http://localhost:11434）
4. 选择嵌入模型（如 nomic-embed-text）

**配置示例**：

```
嵌入提供商: ollama
Ollama URL: http://localhost:11434
模型 ID: nomic-embed-text
模型维度: 768
```

#### 3.1.3 Gemini 配置

**适用场景**：使用 Google 的嵌入服务

**配置步骤**：

1. 选择 "gemini" 作为嵌入提供商
2. 输入 Google AI API 密钥
3. 选择 Gemini 嵌入模型

#### 3.1.4 其他提供商

- **Mistral**：适用于使用 Mistral AI 服务
- **Vercel AI Gateway**：通过 Vercel 的 AI 网关访问多种模型
- **OpenAI Compatible**：兼容 OpenAI API 格式的其他服务

### 3.2 Qdrant 向量数据库设置

#### 3.2.1 本地 Qdrant 配置

**推荐配置**：

```
Qdrant URL: http://localhost:6333
```

**安装 Qdrant**：

```bash
# 使用 Docker 运行 Qdrant
docker run -p 6333:6333 qdrant/qdrant
```

#### 3.2.2 云端 Qdrant 配置

如果使用 Qdrant Cloud：

```
Qdrant URL: https://your-cluster.qdrant.io
API 密钥: your-qdrant-api-key
```

### 3.3 高级配置选项

#### 3.3.1 搜索参数调优

**搜索分数阈值**：

- 默认值：0.7
- 范围：0.0 - 1.0
- 说明：分数越高，搜索结果越精确但可能遗漏相关内容

**最大搜索结果数**：

- 默认值：20
- 范围：1 - 100
- 说明：控制返回的搜索结果数量

#### 3.3.2 索引配置

**文件大小限制**：

- 默认：1MB
- 超过限制的文件将被跳过

**代码块大小**：

- 最大字符数：1000
- 最小字符数：50
- 自动分割长函数和类

## 4. 使用方法

### 4.1 进行代码搜索

#### 4.1.1 通过命令面板搜索

1. 按 `Ctrl+Shift+P` 打开命令面板
2. 输入 "Code Index: Search"
3. 在搜索框中输入查询内容
4. 查看搜索结果

#### 4.1.2 搜索技巧

**功能搜索**：

```
"用户认证"
"数据库连接"
"文件上传"
```

**技术搜索**：

```
"React hooks"
"异步处理"
"错误处理"
```

**具体实现搜索**：

```
"JWT token 验证"
"Redis 缓存"
"API 路由"
```

### 4.2 理解搜索结果

搜索结果包含以下信息：

- **文件路径**：代码所在的文件位置
- **代码片段**：相关的代码块
- **相似度分数**：与查询的匹配程度
- **上下文信息**：函数名、类名等结构信息

### 4.3 索引状态监控

#### 4.3.1 状态指示器

- **待机 (Standby)**：系统就绪，等待操作
- **索引中 (Indexing)**：正在处理文件
- **已索引 (Indexed)**：索引完成，可以搜索
- **错误 (Error)**：出现问题，需要处理

#### 4.3.2 进度监控

在索引过程中，您可以看到：

- 已处理的文件数量
- 总文件数量
- 当前处理的文件
- 预计剩余时间

### 4.4 索引管理操作

#### 4.4.1 重新索引

当代码库发生重大变化时：

1. 在设置中找到 Code Index 部分
2. 点击 "重新索引" 按钮
3. 等待索引完成

#### 4.4.2 清除索引数据

如需清除所有索引数据：

1. 点击 "清除索引数据" 按钮
2. 确认操作
3. 重新开始索引

## 5. 故障排除

### 5.1 常见问题和解决方案

#### 5.1.1 索引失败

**问题**：索引过程中断或失败

**可能原因**：

- API 密钥无效或过期
- 网络连接问题
- Qdrant 服务不可用
- 文件权限问题

**解决方案**：

1. 检查 API 密钥是否正确
2. 验证网络连接
3. 确认 Qdrant 服务正在运行
4. 检查文件访问权限

#### 5.1.2 搜索结果不准确

**问题**：搜索结果与预期不符

**解决方案**：

1. 调整搜索分数阈值
2. 尝试不同的查询词
3. 检查索引是否完整
4. 考虑重新索引

#### 5.1.3 性能问题

**问题**：索引或搜索速度慢

**解决方案**：

1. 检查系统资源使用情况
2. 优化 Qdrant 配置
3. 减少索引文件数量
4. 使用更快的嵌入模型

### 5.2 错误状态处理

#### 5.2.1 配置错误

**错误信息**：配置验证失败

**处理步骤**：

1. 检查所有必需的配置项
2. 验证 API 密钥格式
3. 测试服务连接
4. 重新保存配置

#### 5.2.2 服务连接错误

**错误信息**：无法连接到嵌入服务或 Qdrant

**处理步骤**：

1. 检查服务状态
2. 验证网络连接
3. 检查防火墙设置
4. 重启相关服务

### 5.3 性能优化建议

#### 5.3.1 索引优化

- **选择性索引**：使用 .gitignore 和 .rooignore 排除不需要的文件
- **批量处理**：避免频繁的小批量索引
- **定期维护**：定期清理和重建索引

#### 5.3.2 搜索优化

- **精确查询**：使用具体的技术术语
- **合理阈值**：根据需求调整搜索分数阈值
- **结果限制**：设置合适的最大结果数

## 6. 最佳实践

### 6.1 配置推荐

#### 6.1.1 开发环境配置

**小型项目**（< 1000 文件）：

```
嵌入提供商: ollama
模型: nomic-embed-text
搜索分数阈值: 0.6
最大搜索结果: 15
```

**中型项目**（1000-10000 文件）：

```
嵌入提供商: openai
模型: text-embedding-3-small
搜索分数阈值: 0.7
最大搜索结果: 20
```

**大型项目**（> 10000 文件）：

```
嵌入提供商: openai
模型: text-embedding-3-large
搜索分数阈值: 0.75
最大搜索结果: 25
```

### 6.2 使用技巧

#### 6.2.1 查询优化

**好的查询示例**：

- "用户身份验证逻辑"
- "数据库事务处理"
- "API 错误处理中间件"

**避免的查询**：

- 过于宽泛："函数"
- 过于具体："第123行的变量"

#### 6.2.2 工作流建议

1. **定期更新索引**：每周重新索引一次
2. **监控索引状态**：关注错误和警告信息
3. **优化查询策略**：根据搜索结果调整查询方式
4. **合理使用资源**：避免在系统负载高时进行索引

### 6.3 注意事项

#### 6.3.1 隐私和安全

- **API 密钥安全**：妥善保管 API 密钥，不要提交到版本控制
- **数据隐私**：了解嵌入服务的数据处理政策
- **本地优先**：敏感项目考虑使用 Ollama 等本地方案

#### 6.3.2 资源管理

- **存储空间**：向量数据库会占用一定存储空间
- **网络带宽**：云端嵌入服务会消耗网络流量
- **计算资源**：索引过程会占用 CPU 和内存资源

#### 6.3.3 版本兼容性

- **定期更新**：保持 Kilocode 和相关服务的最新版本
- **配置迁移**：升级时注意配置文件的兼容性
- **功能变更**：关注版本更新日志中的功能变更

## 7. 常见问题解答 (FAQ)

### Q1: Code-Index 支持哪些编程语言？

A: 支持 40+ 种编程语言，包括 JavaScript、Python、Java、C++、Go、Rust 等主流语言，以及 HTML、CSS、Markdown 等文件格式。

### Q2: 如何选择合适的嵌入提供商？

A:

- **追求质量**：选择 OpenAI
- **注重隐私**：选择 Ollama（本地部署）
- **预算有限**：选择开源或免费方案
- **企业环境**：考虑 OpenAI Compatible 方案

### Q3: 索引需要多长时间？

A: 取决于代码库大小和嵌入服务性能：

- 小型项目（< 1000 文件）：1-5 分钟
- 中型项目（1000-10000 文件）：10-30 分钟
- 大型项目（> 10000 文件）：30 分钟以上

### Q4: 如何提高搜索准确性？

A:

- 使用具体的技术术语
- 调整搜索分数阈值
- 确保索引完整和最新
- 尝试不同的查询表达方式

### Q5: Code-Index 会影响 VSCode 性能吗？

A: 正常使用下影响很小，但索引过程中会占用一定系统资源。可以通过以下方式优化：

- 在系统空闲时进行索引
- 排除不必要的文件
- 使用本地嵌入服务

### Q6: 如何备份和恢复索引数据？

A: 索引数据存储在 Qdrant 数据库中，可以通过 Qdrant 的备份功能进行数据备份和恢复。
